Core message

An AI-built app survives real users only when a human fixes its shape first: one repo, infrastructure that is all code on a high abstraction layer, and clients that reach data only through server code. The agent builds well inside a shape. It does not choose one. 3

Surface reading vs the actual argument

SurfaceActual
A tour of Pluto's stack: SvelteKit, Expo, Electron, Convex, Effect, Autumn, WorkOS, Daytona.A selection rule. Pick tools the agent knows, whose setup is code, and keep every part in one repo the agent can read. 3 (28:30, "tools that the agents are very familiar with")

The gap is the lesson. Copy the tool list and you copy 2026's fashion. Copy the rule and it outlives the list.

Falsifiability check

Strongest counterargument. A high abstraction layer moves the failure, it does not remove it. You now depend on a vendor's price, uptime, and security model. He gives no load test. He says plan upgrades will handle scale (29:33), then shows $100 spent on a $20 plan (27:56). The claim "built on solid infra, so no reason it goes down" is a belief. 2 not verified

Second counter. His reason for "client never talks to the DB" is imprecise. In Supabase, the publishable key is meant for the browser, and RLS (row level security, per-row access rules inside Postgres) is the enforcement layer. The key that must never reach the browser is the secret key 5 [2]. So the rule is not "the client never talks to data". It is "the client reaches data only through checks you wrote". His own stack proves it: Convex clients call public functions, and the docs say those "can be called by anyone", so each needs an access check 5 [3].

Competing thesis

Stronger than the lead: agent experience is a fifth design axis. He lists four (scalability, reliability, performance, cost). Every pick he makes is justified by a fifth: can the agent operate it? AWS is "powerful" but "terrible agent experience" (18:22-18:35). Convex wins because "everything is code" (18:49). 3 This is the real payload. Stage 03 takes it as the top alpha idea.

What changes if you believe it

Before the next build, write one table: the four qualities plus agent experience, one line each, with the trade-off you accept. Do it before the first prompt. Then test each tool with one question: can my agent install and run it from a docs link, with config in code?
