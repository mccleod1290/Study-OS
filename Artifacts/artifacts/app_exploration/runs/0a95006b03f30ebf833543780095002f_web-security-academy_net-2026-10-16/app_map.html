1. catalog (public, no login)

product catalog

5GET / → 200 text/html. the public shop front: server-rendered product cards, each "View details" link carries a productId. no parameter on the wire.

product detail

5GET /product?productId=<int> → 200 text/html. one query parameter, productId: a small sequential integer (1, 2, 3 seen). the id selects the product object on the server; each value returns a different page. no JSON, the id is not echoed in a body field. this is the direct object reference the lab is named for — recorded, not swapped.

5GET /image/productcatalog/products/<int>.jpg — product images, also keyed by an integer. the ids are not contiguous (1, 3, 6, 8, 18, 23 … 71 for ~20 products), so the product id space is sparse: real objects sit at scattered integers, not 1..N. static CSS/JS also load under /resources/.

2. account and auth

account gate

5GET /my-account with no session redirects to /login. this is the authentication gate: account data needs a session first. authorization — whose account you see — only matters past this gate, so it is not visible from here.

login form

5GET /login → 200 serves the form. 4POST /login (from the form, not submitted) takes three fields, names only, never values:

3. live chat

chat message (WebSocket)

4wss://<host>/chat — not an HTTP request, so no status. from chat.js plus one harmless "hello": out it sends plain READY on open, then JSON { "message": <string> } (textarea, maxlength 500, html-encoded). in it receives TYPING, a chat line { "user", "content" }, or { "error" }.

transcript

4POST /download-transcript — body field transcript, a client-built string (the message rows). the server writes it to a file and redirects to:

5GET /download-transcript/<int>.txt → 200 text/plain. 2.txt was observed. the transcript id is a sequential integer in the path — a second direct object reference.

from the app's JavaScript (not exercised)

  • 4scripts worth a later read: /resources/js/chat.js, /resources/js/viewTranscript.js.
  • 4window.renderChatMessage(content) — an optional client hook; absent here, so inbound content renders without it.

the object model

two objects are reached by a bare, guessable integer:

  • 5product → productId (int, sequential), query string on /product.
  • 5chat transcript → <int>.txt (int, sequential), path on /download-transcript/.
  • 5product image → <int>.jpg (int, sparse/non-contiguous), path on /image/productcatalog/products/.

three of the app's object paths take a bare integer. two are sequential (transcript, and productId as seen), one is sparse (image). the chat message object has no id: keyed message out, user/content in. the transcript parameter is a free string the server trusts to write the stored file.
